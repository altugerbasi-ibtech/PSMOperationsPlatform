## Objective

Create infrastructure verification scripts executed after deployment.

- Offline safety and contract tests.

## Architectural Boundaries

Scripts verify existing state only. They do not remediate, configure, register,
install, grant, restart, deploy, apply migrations, mutate SQL, or change
runtime behavior. Windows and SQL Collector identities remain separate.

## Verification Contracts

- WinRM performs an authenticated WSMan identification request.
- SPN performs read-only `setspn -Q` lookup and optional owner comparison.
- gMSA checks AD availability, account existence/enabled state, and local
  `Test-ADServiceAccount` readiness.
- Network performs TCP reachability checks for explicitly supplied endpoints.
- SQL uses Windows Integrated Authentication and read-only metadata/migration
  queries against an explicitly supplied database.
- Each script emits structured JSON containing `Status`, `Check`,
  `Target`, `Diagnostics`, and `TimestampUtc`, then exits `0` for `PASS` or
  `1` for `FAIL`.

## Security and Read-Only Requirements

No script accepts SQL passwords or stores credentials. Diagnostics use stable
categories and safe target identifiers without raw exception text. Scripts
must not invoke mutation-capable operational commands or modify files,
services, SPNs, AD, firewall, WinRM, SQL data/schema/permissions, or runtime
configuration.

## Acceptance Criteria

- All five required scripts and the guide exist.
- Each script has deterministic PASS/FAIL exit semantics and detailed
  diagnostics.
- Static tests prove prohibited mutation commands and SQL statements are absent.
- The guide defines prerequisites, parameters, execution order, interpretation,
  evidence handling, and remediation boundaries.
- No runtime or production-code changes occur.
