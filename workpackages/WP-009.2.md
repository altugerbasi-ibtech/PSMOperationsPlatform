## Objective

Produce DBA-quality deployment documentation for the PSM Operations Database.

## Architectural Boundaries

This package creates documentation and read-only validation SQL only. It
changes no runtime behavior, production code, business logic, EF model,
migration, snapshot, database, infrastructure, identity, or permission.
Automatic migrations remain prohibited and the application must never call
`Database.Migrate()`.

## In Scope

- `Release/Database/DeploymentGuide.md`.
- `Release/Database/ValidationQueries.sql`.
- Supported SQL Server baseline, required configuration and permissions.
- Collation, compatibility, recovery, deployment and validation guidance.
- Rollback, version/checksum verification, troubleshooting, and best practices.

## Out of Scope

Live database access, deployment execution, permission mutation, automatic
migration, schema change, rollback execution, runtime modification, and
production certification.

## Requirements

The guide must be directly usable by an authorized DBA while keeping
environment-owned collation and recovery-model choices explicit. Validation
queries must contain read-only metadata and migration-history `SELECT`
statements only and must not remediate findings.

## Persistence and Migration Impact

None. The package documents how a separately authorized DBA may apply the
existing WP-009.1 artifact; it creates no migration or database object.

## Security Requirements

Use Windows Integrated Authentication and an approved deployment identity.
The deployment identity may hold required DDL permissions only for the
controlled change window. Runtime identities receive no DDL permission.
Windows and SQL Collector target permissions remain separate. Documentation
and evidence contain no credentials or connection strings.

## Test and Validation Requirements

Statically verify the required guide sections, read-only SQL, absence of
runtime changes and automatic migration, documentation links, Release build,
all automated tests, and `git diff --check`. No SQL Server contact is allowed.

## Acceptance Criteria

- Both required files exist and are complete.
- The guide covers every user-requested operational topic.
- Environment-defined values are required explicitly rather than invented.
- Validation SQL is read-only and useful before and after deployment.
- No runtime, production-code, EF model, migration, or database changes occur.

## Integration-Pending Items

Actual server values, backup/restore evidence, deployment execution, schema and
permission evidence, rollback execution, and production approval remain under
WP-007.Z or later approved WP-009 packages.

## Required Completion Line

Use `READY FOR WP-009.2 REVIEW` only when every repository criterion passes;
otherwise use `NOT READY`.
