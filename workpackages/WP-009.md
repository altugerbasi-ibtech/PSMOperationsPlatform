## Purpose

Separate deployment and release engineering activities from runtime feature
development. This epic owns the documentation structure for deliverables
required for production deployment, DBA handoff, infrastructure validation,
and release packaging.

## Governing Boundaries

- No runtime behavior changes.
- No feature implementation.
- No business logic modifications.
- No EF automatic migrations.
- No production code changes unless a child package explicitly demonstrates
  that a packaging requirement cannot be met otherwise and receives approval.
- Windows Collector and SQL Collector identities and permissions remain
  separate.
- No real deployment, database mutation, permission change, or privileged
  operation is authorized by creating this epic.

Each child is an independently governed work package. Dependencies,
requirements, validation commands, integration gates, and acceptance criteria
must be completed and approved in that child specification before
implementation begins.

## Epic Scope

- Release artifact preparation and packaging.
- DBA-owned database deployment handoff.
- Read-only schema and database-permission validation.
- Infrastructure and release verification evidence.
- Planning, operational, security, and release documentation for those
  deliverables.

## Epic Exclusions

- Runtime capabilities or behavior.
- Product features and business rules.
- Domain, Application, Collector, Runtime, or UI behavior changes.
- New EF migrations or model changes unless a future approved child
  specification explicitly requires packaging-only metadata.
- Application-owned schema deployment or automatic migration.
- Combining Windows-target and SQL-target permissions under one identity.
- Live production execution merely because a child package exists.

## Sequence

The intended planning sequence is WP-009.1, WP-009.2, WP-009.3, WP-009.4,
WP-009.5, WP-009.6, and WP-009.7. This sequence does not approve implementation or
invent dependencies; each child must declare its approved prerequisites before
launch.

## Completion Criteria

The epic is ready for implementation planning only when every child
specification is complete, internally consistent, reviewed, and individually
approved for implementation. Epic creation alone completes no child package.
