## Objective

Generate a complete deployment package with one repository-root command.

## In Scope

- `Build-Release.ps1`.
- `Release/Database`, `Release/Verification`, `Release/Collector`,
  `Release/Portal`, and `Release/Documentation`.
- Root `Release/Manifest.json`, `Checksums.sha256`, and `Version.txt`.
- Required-artifact validation, SHA256 catalog, release manifest, and
  deployment summary.
- Offline packaging-contract and safety tests.
- `Release/ReleaseGuide.md`.

## Architectural Boundaries

This is build/release orchestration only. It changes no runtime behavior,
feature, business logic, production code, EF model, migration, database,
permission, or infrastructure. It never deploys or executes verification
against live targets.

## Functional Requirements

1. `Build-Release.ps1 -Version <semantic-version>` is the single entry point.
2. It generates the WP-009.1 database package, publishes the Windows Collector
   and Portal projects, includes WP-009.5 verification scripts, and collects
   approved deployment documentation.
3. It fails when any required source or generated artifact is absent.
4. It writes deterministic UTF-8 metadata using the Git commit and its UTC
   timestamp.
5. Root `Manifest.json` records product version, build date, Git commit, and
   every payload artifact's relative path, size, and SHA256.
6. Root `Checksums.sha256` covers every bundle file except itself, including
   root `Manifest.json`.
7. `Version.txt` contains the product version and one terminal newline.
8. `Documentation/DeploymentSummary.md` describes bundle content, validation
   status, execution boundary, and ordered deployment/verification handoff.
9. Generated output directories are cleaned only after their resolved paths
   are proven to be direct children of the repository `Release` directory.

## Security and Determinism

The generator accepts no credential or connection string, contacts no target
infrastructure, and includes no environment secrets. Stable source, version,
toolchain, and release inputs produce stable metadata and normalized ordering.
The checksum catalog cannot hash itself.

## Acceptance Criteria

- One command creates every required directory and root artifact.
- Collector and Portal publish outputs are present.
- Database, verification, and documentation deliverables are included.
- Missing artifacts fail the build.
- SHA256, manifest, version, and deployment summary contracts are tested.
- No runtime or production-code changes occur.

## Integration-Pending Items

Actual bundle generation from a clean immutable release commit, artifact
signing, deployment, live verification, evidence acceptance, and production
certification remain under the release gate.
