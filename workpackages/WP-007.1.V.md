## Objective

Provide a standalone DBA-executed SQL package that reports one overall PASS or
FAIL and, on failure, every detected database configuration and schema defect.

## Business and Product Value

Release approval needs independent evidence that a target matches the approved
database contract without granting the application schema-management rights.

## Existing Repository Context

The authority is the 17 ordered EF migrations, current model snapshot,
`PSMOperationsDatabaseSchemaExpectation.json`, SQL Server 2022 baseline, and
controlled-migration architecture. Collation and recovery model remain
deployment-defined and therefore must be supplied explicitly by the DBA.

## Architectural Boundaries

This package is release infrastructure only. It changes no runtime project,
application behavior, EF model, migration, snapshot, identity, or permission.
Automatic migration and application-owned DDL remain prohibited.

## In Scope

- `Release/Database/SchemaValidation.sql`.
- `Release/Database/SchemaValidation.md`.
- Offline static regression tests and repository index updates.

## Out of Scope

Database mutation, migration application, automatic remediation, permission
granting, connectivity tooling, rollback execution, and WP-007.Z execution.

## Functional Requirements

The SQLCMD-compatible script requires an expected database name, collation,
and recovery model. Compatibility level 160 and latest migration
`20260729191745_WP0088ExecutionHistory` are repository-owned defaults. It
validates database existence and name, compatibility, collation, recovery,
migration history and exact ordered migration set, required tables, critical
indexes, critical foreign keys, unique constraints, and persistent defaults.
It returns one overall PASS or FAIL result set, followed only on failure by all
diagnostics in deterministic category/object order.

## Domain and Application Contracts

No Domain or Application contract changes. Diagnostic rows contain Category,
ObjectName, ExpectedValue, ActualValue, and Diagnostic.

## Persistence and Migration Impact

None. No migration, model snapshot, entity, mapping, or database object is
created, altered, or dropped.

## Failure Classification

Failures are classified as Configuration, Database, Migration, Table, Index,
ForeignKey, UniqueConstraint, or DefaultConstraint. Missing prerequisites do
not suppress independent checks that remain safe to run.

## Security and Read-Only Requirements

The script contains only metadata reads and table-variable diagnostics. It
contains no DDL, DML against target objects, stored procedure execution,
automatic migration, credential, connection string, or secret.

## Determinism and Immutability

Expectations are immutable literal sets derived from the repository contract.
Output is ordered ordinally and contains no time, machine, user, or random
data.

## Cancellation

The DBA client owns cancellation. No work continues outside the SQL batch.

## Logging, Events and Observability

The two result shapes are the complete output contract. The script emits no
SQL text, credentials, connection strings, or target data.

## Test Requirements

Static tests verify every validation category, latest migration, object counts,
PASS/FAIL contract, read-only syntax, absence of automatic migration, and
documentation completeness without contacting SQL Server.

## Documentation Requirements

The DBA guide documents required variables, execution methods, permissions,
result interpretation, evidence capture, limitations, and WP-007.Z boundary.

## Validation Commands

Run targeted and complete Pester tests, Release build and .NET tests,
documentation link validation, prohibited-SQL scan, migration/model diff scan,
and `git diff --check`. Do not connect to SQL Server.

## Acceptance Criteria

- Both required release files exist.
- Every requested validation is implemented.
- One overall PASS or FAIL is returned.
- FAIL returns all detected diagnostics.
- Static validation proves the target batch is read-only.
- No runtime, EF model, migration, or application behavior changes.

## Integration-Pending Items

DBA execution, evidence capture, actual configuration values, permissions,
performance, and production certification remain WP-007.Z responsibilities.

## Remaining Risks

Repository expectations embedded in the script must be updated with future
approved migrations. Metadata visibility depends on the executing DBA's
permissions; lack of visibility can appear as missing objects.

## Final Report Requirements

Report files, validation evidence, object counts, test results, database/model
impact, limitations, diff, status, and prohibited actions.
