## Objective

Add one mandatory production-readiness decision to every Release Acceptance
Test output.

## Mapping

| Overall Result | Status | Message | Exit Code |
|---|---|---|---|
| PASS | `READY_FOR_PRODUCTION` | `PSM Release Status: READY FOR PRODUCTION` | 0 |
| WARNING | `READY_WITH_WARNINGS` | `PSM Release Status: READY WITH WARNINGS` | 1 |
| FAIL | `NOT_READY_FOR_PRODUCTION` | `PSM Release Status: NOT READY FOR PRODUCTION` | 2 |

The mapping is centralized. A FAIL must never produce either ready decision.

## Requirements

- Compute overall result from supplied checks with severity order
  `FAIL > WARNING > PASS`.
- Treat absent mandatory read-only validation evidence as FAIL.
- Include `OverallResult`, `ProductionReadinessStatus`, and
  `ProductionReadinessMessage` in JSON.
- Display explicit decision text at the top and final summary of HTML.
- Start Markdown with `# Production Readiness Decision` and the bold message.
- Finish console output with the required separator/message block.
- Preserve exit codes 0, 1, and 2.
- Keep HTML meaningful without CSS and when printed.
- Update the guide, samples, tests, and completion report.

## Architectural and Safety Boundaries

WP-009.7 aggregates supplied read-only results and writes local report files.
It performs no environment check, remediation, deployment, SQL operation,
runtime change, feature implementation, or production-code modification.

## Acceptance Criteria

- All four output forms contain the same mapped decision.
- Automated tests cover PASS, WARNING, and FAIL mappings.
- FAIL-to-ready regression protection is explicit.
- Read-only validation remains mandatory.
- Documentation and samples show all three outcomes.
- No runtime or environment changes occur.

## Required Completion Line

Use `READY FOR WP-009.7 REVIEW` only when all repository criteria pass;
otherwise use `NOT READY`.
