## Objective

Extend the standard Operational Validation Toolkit with repository-owned,
bounded validation of correctness under synthetic concurrency and scale across
Runtime, Dispatcher, Monitoring, History, retention, inventory replacement,
validation tooling, SQL query safety, and release tooling. The output determines
whether the repository is prepared for controlled performance testing; it does
not establish production performance or scale.

## Business and Product Value

Performance risks often appear first as lost bounds, incorrect concurrency,
cardinality growth, unstable ordering, unbounded queries, retained state, or
slow failure paths. A deterministic repository preflight catches those defects
before live testing while keeping machine-variable microbenchmarks advisory and
preventing developer-machine results from becoming unsupported capacity claims.

Repository facts at specification approval time:

- BenchmarkDotNet is not present and is not authorized by this package;
- Monitoring budgets are advisory local goals: metric-only median under 1 ms,
  Activity-enabled median under 2 ms, health update under 1 ms, snapshot under
  5 ms, and health/readiness evaluation comfortably below 5 ms;
- the existing enforced Monitoring guard runs 10,000 fixed synthetic
  calculations within a generous 15-second correctness-oriented bound;
- Runtime parallel policies are `SerialCore=1` and `ParallelReadOnlyA=2`;
  throttle limits are Lightweight=4, Standard=2 and Heavy=1;
- batching is inactive; the validator cannot activate it;
- Windows Collector connectivity probes are independently bounded at 20;
- History paging defaults to 50 and caps at 200;
- History retention defaults to batch 500 and policy validation caps at 5000;
- Monitoring collections and recent windows are already bounded; no exporter,
  backend or network dependency exists;
- History has no production cleanup scheduler and live retention deletion is
  outside this package;
- no repository convention supports allocation values or one-shot elapsed time
  as a hard cross-machine CI gate.

The validator must observe these facts and current tests/source. It cannot
change budgets, policies, limits, query behavior, retention, or runtime code.

## Architectural Boundaries

- Extend WP-007.Z.3 only; no generic benchmark framework, scheduler, Runtime,
  Monitoring system, load service, performance database or distributed agent.
- Correctness and boundedness gates are authoritative. Machine-variable timing
  is informational/advisory unless an existing approved deterministic guard
  already enforces it.
- Synthetic repository-local operations use existing contracts, fake plugins,
  fake handlers, listeners, fixed TimeProvider and test fixtures. No Collector,
  target, Portal, IIS, WinRM, AD, live SQL or backend access.
- PowerShell orchestrates existing tests/source checks and reports results; it
  does not duplicate Runtime scheduling, health, projection, query, paging,
  retention or release logic.
- Profile values are validation workload bounds, not supported product limits,
  capacity guarantees, production sizing or policy overrides.
- No Runtime/Dispatcher/Monitoring/History/inventory/release ownership change,
  new lock or dependency direction.
- A discovered performance defect is reported. This package does not authorize
  runtime fixes; any required fix needs an approved amendment before changes.

Profiles use exact approved specification values:

| Profile | Targets | Runs | Steps/run | Synthetic orchestration parallelism | Warmup | Measurements | Expected repository duration | Classification |
|---|---:|---:|---:|---:|---:|---:|---|---|
| Smoke | 5 | 10 | 5 | 1 | 1 | 3 | normally under 2 minutes | correctness/boundedness enforced; timing advisory |
| Standard | 20 | 100 | 10 | 2 | 2 | 5 | normally under 10 minutes | correctness/boundedness enforced; timing advisory |
| Extended | 100 | 1000 | 20 | 4 | 3 | 7 | environment-dependent, bounded maximum 30 minutes | opt-in informational timing; correctness enforced |

These values become repository-validation defaults only upon human approval of
this specification. They do not modify Runtime policies (1/2), throttle limits
(4/2/1), Collector probe limit (20), page max (200), retention batch rules or
product capacity. Extended is never a normal-build requirement.

The schema/template/sample/validator/tests/docs change together. Sample values
use Smoke and contain no machine capacity. Reject unknown/duplicate profile
definitions, custom profile names, zero/negative/above-max counts, profile/value
mismatch, unlimited sentinel values, live/query-plan true, credentials,
connection strings, tokens, environment resource values and paths.

Command-line `-ValidationProfile`, when supplied, may select only one of the
three definitions and must exactly replace all profile workload values with the
code-owned table; it cannot create a custom/extreme workload. Configuration is
validated before workload construction.

unit and environment caveat. No machine identity or raw samples are persisted.

## Functional Requirements and Validation Categories

### 1. Performance Configuration

Validate the object/profile/exact values, all numeric bounds, output path via
common path checks, no unsafe unlimited/live/query-plan values, secrets,
environment resource sizing or duplicate definitions. Fail before synthetic
workload. `OutputPath` is local report output, not performance evidence config.

### 2. Runtime Execution Overhead

Use existing fake handlers/plugins and deterministic terminal scenarios to
validate run/step/attempt, timeout, retry, cancellation, dependency, throttle
and state-transition correctness under the selected bounded profile. No target
or production Collector. Record Stopwatch summary only when informational
benchmarks are enabled; correctness first.

### 3. Dispatcher Performance

Observe tests/source for explicit handler lookup, plugin/SDK/policy validation,
context construction and rejection path. Validate bounded collections/memory
by contract, no repeated reflection scan, dynamic loading or service-locator
hot path. Do not alter Dispatcher responsibilities or invent timing gates.

### 4. Runtime Concurrency

Use bounded fake handlers to prove policy concurrency 1/2 and throttle 4/2/1,
dependency order, completion without deadlock, cancellation/timeout waiter
release, retry delay outside critical lock, bounded task creation, accurate
active counts and disposable primitives. Test timeout is profile-bounded and
does not change product timeout policy.

### 5. Runtime Memory and Allocation

Inspect contracts/tests for bounded per-run/step/event/retry state, no raw
artifact copy into Monitoring, no static completed-run accumulation and no
retention beyond owners. Optional allocation observations are informational;
no LOH/allocation hard gate exists. Correctness bounds still fail if violated.

### 6. Monitoring Overhead

Reuse existing Monitoring performance tests and approved budgets. Validate
metric-only, Activity-enabled, health update, snapshot, health/readiness,
bounded windows, concurrent readers, cardinality, no network/exporter and
failure isolation. Preserve the 10,000/15-second correctness guard. Advisory
millisecond goals produce WARNING on stable synthetic exceedance, not unstable
cross-machine FAIL.

### 7. Monitoring Cardinality at Scale

Use code-owned synthetic registered strategy/plugin values across increased
run counts. Prove allowed tag keys/value domains remain bounded and prohibit
run/server/FQDN/artifact/file/path/exception/arbitrary metadata dimensions.
Increasing run count must not create a new dimension value set. No exporter.

### 8. Execution History Projection Performance

Reuse WP-008.8 projection tests/fakes for terminal mapping, bounded input/
transaction scope, duplicate/Partial behavior, no transaction across Collector
execution, no raw event retention and failure isolation. Do not write live SQL
or make elapsed thresholds without authority.

### 9. Execution History Query Performance Readiness

Observe `AsNoTracking`, page 50/max 200, bounded date range, deterministic
`CompletedAt DESC` plus run ID, no IQueryable/dynamic language/unbounded Include,
source/test N+1 evidence and supporting migration indexes. SQL plan/live latency
remain NOT_APPLICABLE without authorization.

### 10. Retention Performance Readiness

Validate policy default batch 500/max 5000, bounded `Take`, TimeProvider stable
cutoff, child-before-parent order, cancellation, idempotency, short transaction,
no external call/scheduler/live deletion. Reuse WP-007.Z.8 authority when
implemented; otherwise observe WP-008.8 source/tests directly without
duplicating retention rules.

### 11. Inventory Replacement Scale Readiness

Observe target-scoped replacement, input validation, ordering, transaction,
duplicate behavior, documented materialization/memory limits, no cross-target
full-table load and no target write. Use synthetic store tests only; no real
inventory collection or semantic change.

### 12. Validation Toolkit Scale

With mocked targets generate result sets exactly bounded by profile target and
registered check counts. Validate aggregation, deterministic JSON/Markdown,
duplicate IDs, sanitization, independent failures, bounded per-run log, no
scanning/uncontrolled parallel remote checks. Cap synthetic results at 20,000
for Extended; exceeding the derived cap fails before allocation. This is a
validator safety cap, not product capacity.

### 13. Release Bundle and RAT Performance

Reuse release Pester tests for deterministic bounded checksum/manifest/bundle
and RAT aggregation/reporting across registered modules. Validate generated
build output exclusion and no remote dependency. Do not create a release format
or publish artifacts.

### 14. SQL Query Safety and Cost Awareness

Statically inspect repository validation/Collector/history queries: explicit
bounded TOP/filters where row data is read, sargable date predicates, no
`SELECT *`, unbounded cross join/cursor/recursive CTE/dynamic SQL, cache-clearing
DBCC/blocking diagnostic/mutation. Catalog single-row metadata selects need not
invent TOP. Report only; do not rewrite queries or execute live SQL.

### 15. Lock and Contention Review

Source/tests validate no global/critical lock spans external callback, WinRM,
SQL target access, retry delay, timeout wait or target execution transaction;
bounded semaphores; cancellation release; concurrent readers. Do not add locks
or claim live contention evidence.

### 16. Time and Duration Correctness

Validate TimeProvider for business/cutoff/health logic, Stopwatch for optional
elapsed measurement, nonnegative/consistent queue/wait/attempt/step/run
durations, bounded timeout and clock-change deterministic tests. Preserve
repository UTC persistence and Türkiye-local presentation policy from current
ADR/docs; do not change timestamp rules.

### 17. Failure-Path Performance

Use bounded synthetic immediate/retry-exhaustion/timeout/cancellation/plugin-
validation/rejection/Monitoring/History/report failures. Prove no task/session/
listener/resource leak, bounded safe diagnostics, no repeated raw exception
construction and no indefinite unrelated blocking. Correctness failures FAIL;
timing remains advisory.

### 18. Long-Running and Uncooperative Plugin Boundary

Reuse LongRunning/Cancellation sample tests. Validate cooperative cancellation
and timeout classification, and document that an uncooperative in-process
plugin cannot be forcibly terminated. Do not claim hard isolation, terminate
processes or create worker-process architecture. This limitation yields an
explicit warning/informational readiness caveat, not a hidden feature.

### 19. Scale Matrix

Generate `docs/validation/WP-007.Z.9-Scale-Matrix.md` from code-owned profile
definitions or a checked-in deterministic template. Dimensions: targets,
runs, steps, attempts (bounded by existing retry max 2), registered plugins/
strategies used by fixtures, Monitoring events, History projection records,
page 50/200, retention 500/max 5000, report results max 20,000. For each list
repository-tested value, enforcement, future live need, limitation and
`NO PRODUCTION CLAIM`. Do not state unsupported product maximums.

### 20. Performance Budget Evaluation

Evaluate only approved Monitoring budgets/10,000 guard and any existing
deterministic test timeout. Report target, synthetic median/p95 if valid,
profile, enforced versus advisory and caveat. No new architecture budget.
Noisy/advisory exceedance WARNING; deterministic correctness/bound failure
FAIL. `EnableInformationalBenchmarks` false yields NOT_APPLICABLE timing while
correctness tests still run.

### 21. Performance and Scale Readiness

Consolidate repository checks complete, informational variability and skipped
categories. Always state live target/WinRM/SQL/IIS/Portal latency, SQL plans,
real target count, throughput and resource sizing are not established. Output
PASS/WARNING/FAIL for repository readiness only. Production scale readiness is
`NOT PROVEN` absent separately authorized evidence.

## Cancellation and Resource Bounds

report results; no unbounded task creation. Dispose Meter/Activity listeners,
semaphores, cancellation sources, fake hosts, streams and files. Cancellation
stops between bounded units, releases waiters and never triggers Runtime or
remote cancellation. Do not use arbitrary sleeps as measurement.
