# WP-007.Z.9 Performance and Scale Validation

Run the repository-local validator from Windows PowerShell 5.1:

```powershell
.\tools\validation\performance\Invoke-PerformanceScaleValidation.ps1 -ConfigurationPath .\Release\Deployment\DeploymentConfiguration.sample.json -OutputPath <local-output>
```

`-ValidationProfile Smoke|Standard|Extended` selects an exact code-owned
profile. Skip switches isolate Runtime, Monitoring, History, database-static,
or tooling checks. `-EnableInformationalBenchmarks` enables only advisory,
machine-sensitive observations. Profile values are validation inputs, not
product limits.

The command checks configuration, Runtime/Dispatcher boundedness, concurrency,
Monitoring budgets/cardinality, History query/projection bounds, retention,
inventory replacement, validation/release tooling, SQL safety, locks, time,
failure paths, plugin cancellation boundaries, the scale matrix, budgets and
overall repository readiness. It uses synthetic/local source and test evidence;
it contacts no target, database, IIS, WinRM, AD, Portal or backend.

Reports are `PerformanceScaleValidationReport.json`, `.md`, and `.log`. Exit
codes are 0 PASS, 1 WARNING, 2 FAIL, 3 invalid configuration and 4 execution
error. Live latency, SQL plans, throughput and sizing need separately authorized
controlled evidence. Production scale readiness is not proven by this command.

Troubleshoot configuration failures by validating the shared deployment file.
Correctness failures identify the repository authority to restore. Timing
warnings should be repeated in a controlled environment; they are not stable CI
gates. Never enable live flags, mutation, retention cleanup, external exporters,
production collectors or load generation through this validator.
