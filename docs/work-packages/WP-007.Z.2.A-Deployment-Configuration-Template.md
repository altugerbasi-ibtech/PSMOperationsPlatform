# WP-007.Z.2.A Deployment Configuration Template

## Objective

Establish one reusable, schema-defined deployment configuration as the
authoritative environment-input contract for release engineering, database
deployment, validation, and future Collector and Portal installation tooling.

## Deliverables

- `Release/Deployment/DeploymentConfiguration.template.json`
- `Release/Deployment/DeploymentConfiguration.sample.json`
- `Release/Deployment/DeploymentConfiguration.schema.json`
- `Release/Deployment/DeploymentConfiguration.md`
- `Release/Deployment/Test-DeploymentConfiguration.ps1`
- offline Pester contract and negative validation tests

## Boundaries

This package changes no runtime project, application behaviour, EF migration,
database object, infrastructure, identity, or permission. It performs no live
connection or deployment. Populated environment configuration, secrets,
passwords, connection strings, and certificates are prohibited from source
control.

## Contract

Operators copy the generic template to controlled storage, populate every
required environment value, validate it, and reuse the same approved copy for
WP-009.2, WP-009.3, WP-009.4, WP-009.5, WP-009.7, and WP-007.Z.2. Future
Windows Collector, SQL Collector, and Portal installers must consume the same
model rather than define competing configuration.

The JSON Schema defines all sections, required values, types, formats, allowed
recovery models, Boolean values, and port ranges. The read-only validator
detects invalid JSON, missing or empty required values, schema violations,
invalid SQL/WinRM ports, duplicate server roles, empty service accounts, and
identity reuse.

## Acceptance Criteria

- Template remains generic and contains no environment-specific values.
- Sample is schema-valid and uses only reserved/synthetic example values.
- Unknown properties and missing required properties are rejected.
- SQL and WinRM ports must be integers from 1 through 65535.
- Runtime server roles and service accounts are distinct.
- Windows authentication remains required.
- Focused release tests and all repository tests pass.
- No commit, push, tag, live deployment, or runtime change occurs.
