# WP-007.Z.8 History and Retention Validation

Run from Windows PowerShell 5.1 under the approved Operations Database identity:

```powershell
.\tools\validation\history\Invoke-HistoryRetentionValidation.ps1 -ConfigurationPath <approved-json> -OutputPath <external-output> [-DatabaseTarget <configured-name>]
```

Skip switches for schema, projection, query and retention checks produce
structured skips. The command selects only the configured Operations Database
target and reuses Windows Authentication, Kerberos, TLS, schema and permission
authorities.

Checks cover schema version 1, migration `20260729191745_WP0088ExecutionHistory`,
six tables, keys/indexes, projections, idempotency, Partial semantics,
transitions, artifact metadata, provenance, bounded queries, paging 50/200,
retention 180/90/90, batch 500/max 5000, cleanup safety, failure isolation,
Monitoring separation and History-versus-Audit boundaries.

The validator never runs a Collector, projection, migration, cleanup or data
mutation. No dry-run API exists, so that check is `NOT_APPLICABLE`. The separate
pre-existing Audit capability is allowed; only History schema/dependency leakage
is rejected. Reports are `HistoryRetentionValidationReport.json`, `.md` and
`.log`; exits are 0 PASS, 1 WARNING, 2 FAIL, 3 invalid configuration and 4
execution error.

Repository evidence cannot prove deployed schema, permissions, concurrency,
query plans, locks, performance or retention throughput. Live or destructive
validation needs separate authorization. Never add credentials, SQL
Authentication, write SQL, scheduler jobs or populated live evidence.
