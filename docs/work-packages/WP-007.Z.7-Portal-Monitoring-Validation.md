# WP-007.Z.7 Portal & Monitoring Validation

## Purpose and current capability

This read-only command extends the WP-007.Z.3 toolkit. It validates the
configured singleton Portal, its Operations database boundary, and the
repository's existing Execution Monitoring contracts without adding runtime
features or contacting a monitoring backend.

Current facts are deliberately visible:

- the Web host exposes only generic `/health`;
- no dedicated Portal Monitoring endpoint exists;
- Windows Authentication is composed through the IIS default scheme, an
  authenticated fallback policy, and correctly ordered middleware; live IIS and
  HTTP Kerberos validation remain unexecuted;
- no production exporter or monitoring backend exists.

Consequently repository success is not production Portal or Monitoring
success. Missing deployed capabilities produce the specified
`NOT_APPLICABLE`, `WARNING`, or `FAIL` result.

## Command

```powershell
.\tools\validation\portal\Invoke-PortalMonitoringValidation.ps1 `
  -ConfigurationPath '<CONTROLLED>\DeploymentConfiguration.json' `
  -OutputPath '<APPROVED-EVIDENCE-DIRECTORY>' `
  -PortalName '<CONFIGURED-PORTAL-NAME>' `
  -Verbose
```

Omit `PortalName` to select the enabled singleton Portal. Optional
`SkipPortalChecks`, `SkipMonitoringChecks`, and `SkipDatabaseChecks` emit
explicit skipped evidence; mandatory skipped evidence prevents an unqualified
pass. Configuration and selection are validated before contact.

## Hosting, authentication, and database

The configured hosting model is `AspNetCoreIIS`, HTTPS with normal certificate
and hostname validation, bounded redirects/timeouts, and current-process
identity. Portal host/IIS evidence reuses WP-007.Z.4. Operations database
evidence reuses WP-007.Z.5 plus WP-009 schema and Portal permission validators.

Windows Authentication is required by policy. Repository validation now proves
scheme registration, authentication/authorization middleware and order,
authenticated fallback policy, and explicit generic health anonymity. It still
validates live deployment separately and does not treat source composition as
IIS or Kerberos evidence. This package validates its
absence in current Web composition and does not implement or enable it. It
does not accept credentials, enable Basic/Anonymous Authentication, bypass
TLS, modify IIS, deploy Portal files, run migrations, or grant permissions.

## Monitoring validation

Repository checks observe the code-owned `PSMOperationsPlatform.Execution`
version `1.0` identity, schema versions, metric catalog, `Meter` and
`ActivitySource`, logging/Monitoring subscriber composition, immutable
snapshot boundary, existing advisory health assessment, and
`execution-monitoring` Collector health registration. Existing solution tests
provide the in-process listener, event mapping, isolation, concurrency,
cardinality, and health behavior evidence. PowerShell does not duplicate those
algorithms.

No exporter/backend is the approved default. Expected-but-absent configuration
fails. A configured-but-unvalidated backend cannot be reported operational,
and this command never sends metrics or traces remotely.

## Results

The output directory receives:

- `PortalMonitoringValidationReport.json`;
- `PortalMonitoringValidationReport.md`;
- `PortalMonitoringValidation.log`.

The console ends with `PORTAL AND MONITORING VALIDATION: PASS`, `WARNING`, or
`FAIL`. Exit codes are 0 pass, 1 warning, 2 fail, 3 invalid configuration or
selection, and 4 execution error. Reports use sanitized results and never
include HTTP bodies, full configuration, live metric/trace values, connection
strings, certificate material, or credentials.

## Troubleshooting and evidence

- Correct configuration only in the controlled deployment file.
- Resolve host/IIS/HTTPS/authentication findings through approved Portal work.
- Resolve schema/permission findings through WP-009/DBA procedures.
- Restore Monitoring contracts in their owning approved package; do not add a
  parallel health or metric implementation.
- Do not enable an exporter/backend merely to satisfy validation.

Use `artifacts/validation/WP-007.Z.7/` as sanitized scaffolding only. Keep live
reports and topology externally. Live Portal and Monitoring validation were
not executed during repository implementation.
