# Portal Windows Authentication Composition

The Portal is a .NET 10 ASP.NET Core Minimal API hosted through IIS. It uses the
framework IIS Integration scheme (`IISDefaults.AuthenticationScheme`) and adds
no Negotiate, cookie, bearer, Basic, Forms, or vendor authentication package.

`AddPortalWindowsAuthentication` registers authentication and an authorization
fallback policy that requires an authenticated user. The application calls
`UseAuthentication` before `UseAuthorization`, before endpoint mapping. All
routes are protected by fallback unless they have explicit anonymous metadata.

The existing generic `/health` endpoint is the sole anonymous endpoint. It is
explicitly marked `AllowAnonymous`, returns only bounded framework liveness
text, and has no target, database, migration, or diagnostic-detail check.

Unauthenticated protected requests return 401. An authenticated principal may
reach a protected endpoint; an explicit denying policy returns 403. WP-010.1
adds no roles, groups, UI, login, claims logging, impersonation, forwarded-user
headers, Blazor services, or token serialization.

Production IIS deployment must enable Windows Authentication, disable Anonymous
Authentication for protected Portal access, disable Basic Authentication, use
no Forms Authentication, retain HTTPS certificate validation, and use the
approved Portal application-pool identity. The SDK-generated `web.config`
convention remains unchanged.

Local Kestrel Development is not production Windows-authentication evidence.
Repository tests use a test-assembly-only scheme without credentials or identity
headers. Live IIS validation must prove Windows Authentication and 401/403/health
behavior; live transport evidence must separately establish Kerberos versus
NTLM. Neither was executed by this package.

WP-007.Z.7 and WP-007.Z.10 now require scheme registration, both middleware,
correct order, authenticated fallback policy, and explicit health anonymity.
This closes the repository composition defect only. Monitoring risk acceptance,
operational sign-offs, RAT, all live evidence, and scale proof remain separate.
