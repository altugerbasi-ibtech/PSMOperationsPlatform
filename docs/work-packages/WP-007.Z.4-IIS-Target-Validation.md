# WP-007.Z.4 IIS Target Validation

## Purpose and boundary

`Invoke-IISTargetValidation.ps1` extends the WP-007.Z.3 operational validation
framework with read-only IIS target preflight. It validates only targets in the
shared deployment configuration. It does not run the Collector, change IIS or
Windows, inspect an application database, or remediate a finding.

Repository tests mock DNS, TCP, WSMan, Kerberos, IIS, registry, filesystem,
network, and remote PowerShell. Passing repository tests does not mean that a
live IIS target passed validation.

## Configuration

Populate `IisTargets` in the controlled copy of
`Release/Deployment/DeploymentConfiguration.json`. It is a non-empty array of
unique DNS/server names. Do not commit the populated file. Global `Security`
settings require Windows Authentication, Kerberos-only authentication, the
approved WinRM port, `IncludePortInSPN=true`, and the approved TLS policy.

Validate configuration before use:

```powershell
.\Release\Deployment\Test-DeploymentConfiguration.ps1 `
  -Path '<CONTROLLED>\DeploymentConfiguration.json'
```

## Command

Validate every configured IIS target:

```powershell
.\tools\validation\iis\Invoke-IISTargetValidation.ps1 `
  -ConfigurationPath '<CONTROLLED>\DeploymentConfiguration.json' `
  -OutputPath '<APPROVED-EVIDENCE-DIRECTORY>' `
  -Verbose
```

Validate one target already present in `IisTargets`:

```powershell
.\tools\validation\iis\Invoke-IISTargetValidation.ps1 `
  -ConfigurationPath '<CONTROLLED>\DeploymentConfiguration.json' `
  -ComputerName '<CONFIGURED-IIS-TARGET>' `
  -OutputPath '<APPROVED-EVIDENCE-DIRECTORY>' `
  -Verbose
```

An unconfigured `ComputerName` is rejected before environment contact.
Targets are processed deterministically. One failed target does not prevent
the remaining configured targets from being evaluated.

## Authentication and remote execution

The command uses only PowerShell remoting with explicit Kerberos,
`IncludePortInSPN`, the configured port, and TLS exactly when configured. It
does not use authentication fallback, TrustedHosts, DCOM, SSH, copied target
scripts, temporary target files, or target-side agents. Sessions are closed in
`finally`.

## Checks

The report covers:

1. forward/reverse DNS, WinRM TCP, WSMan, Kerberos, and remote session;
2. Windows Server support, x64, last boot, pending reboot, domain, time zone,
   and locale;
3. IIS role, W3SVC, IIS version, and management API availability;
4. sites, applications, virtual directories, bindings, host headers, HTTP,
   and HTTPS;
5. pool runtime, pipeline, identity type/name, gMSA form, state, auto-start,
   and periodic recycling;
6. worker-process PID, pool mapping, and state;
7. installed .NET Framework and .NET shared-host runtime metadata;
8. site logging, log paths, access, and free-space observations;
9. Windows, Anonymous, Basic, client-certificate, and pool-identity settings;
10. IIS physical/log path existence, readability, and free space;
11. DNS/TCP-only reachability of the configured SQL endpoint; and
12. advisory Collector compatibility derived from mandatory check IDs.

Only repository-documented expectations are enforced. No disk-space,
retention, uptime, locale, time-zone, host-header, application-runtime, or
worker-process minimum is invented. Unknown application requirements remain
unknown. Basic Authentication enabled is reported as a warning and is never
used by the validator.

## Reports and exit codes

The output directory contains only:

- `IISTargetValidationReport.json`;
- `IISTargetValidationReport.md`; and
- `IISTargetValidation.log`.

The console ends with `IIS TARGET VALIDATION: PASS`, `WARNING`, or `FAIL`.

| Code | Meaning |
|---:|---|
| 0 | `PASS` |
| 1 | `WARNING` |
| 2 | `FAIL` |
| 3 | `INVALID_CONFIGURATION` or invalid target selection |
| 4 | `EXECUTION_ERROR` |

`PASS` is a point-in-time prerequisite result, not permission to start the
Collector. Missing reverse DNS is a warning when forward DNS remains usable.
Remote authentication failure fails connectivity and marks dependent remote
categories `SKIPPED`; SQL DNS/TCP remains independently evaluated.

## Evidence and safety

Use `artifacts/validation/WP-007.Z.4/` only for sanitized templates. Store live
reports in the approved external evidence directory. Reports store the
configuration SHA256 rather than configuration content and must not contain
credentials, tickets, private keys, application data, connection strings, or
unbounded remote output.

No live IIS validation was performed during repository implementation.
