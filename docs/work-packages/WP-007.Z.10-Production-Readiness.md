# Production Readiness Validation

`tools/validation/production/Invoke-ProductionReadinessValidation.ps1` aggregates existing repository, release, live-environment, RAT, and human-approval evidence. It does not execute live validation or implement missing capabilities.

```powershell
.\tools\validation\production\Invoke-ProductionReadinessValidation.ps1 `
  -ConfigurationPath .\Release\Deployment\DeploymentConfiguration.sample.json `
  -EvidenceRoot C:\ApprovedEvidence `
  -ReleaseVersion 1.0.0 `
  -GoldenBaselineCommit <approved-commit> `
  -OutputPath C:\ValidationOutput
```

Exit codes are `0` ready, `1` ready with warnings, `2` not ready or insufficient live evidence, `3` invalid configuration, and `4` execution error. Reports are JSON, Markdown, and log files. Evidence must align on release, commit, configuration hash, timestamp, and result.

Decision precedence is mandatory capability/security failure, then missing mandatory live evidence, then accepted warnings, then ready. Repository-only, mocked, or synthetic evidence never establishes production readiness.

Current repository facts produce `NOT_READY_FOR_PRODUCTION`: Portal Windows Authentication is documented but is not composed in the Web host. The generic `/health` endpoint is the only Portal health endpoint. No production Monitoring exporter/backend, retention dry-run API, or production retention scheduler exists. Production scale readiness is not proven.

The command is read-only except for local report output. It does not deploy, contact live systems, execute Collector workloads, mutate SQL/IIS/services, configure authentication or exporters, accept risks, or create approvals.
