# WP-005.5 - Processor Inventory

`ProcessorInventoryModule` reuses the successful target WinRM session and
executes one allowlisted object projection:

`Get-CimInstance -ClassName Win32_Processor -Property
DeviceID,Name,Manufacturer,NumberOfCores,NumberOfLogicalProcessors,MaxClockSpeed`

No wildcard, formatting command, string parser or human-readable output is
used. SocketDesignation is not projected because the implemented entity has no
corresponding field.

## Stable source key

`DeviceID` is the target-scoped `StableSourceKey`. This matches the existing
WP-005 data-model decision and the Microsoft `Win32_Processor` schema, where
DeviceID has the CIM `Key` qualifier and identifies a processor within the
system.

ProcessorId is not selected because it is hardware/firmware-derived and may be
unavailable. Name is display data. SocketDesignation is descriptive. A CIM
path adds provider serialization without improving on the class key.

Reference: [Microsoft Win32_Processor class](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-processor).

Blank, surrounding-whitespace, over-length or case-insensitive duplicate
DeviceID values fail before persistence.

`DeviceID` is stable only within the target/provider lifecycle; processor
replacement, firmware/provider remapping or operating-system reconstruction
may produce a different key. WP-005 treats that as a new current source
identity and does not claim immutable hardware identity across those events.

## Normalization and validation

Each object maps explicitly to `ProcessorInventoryItem`. Name and Manufacturer
are optional but cannot be whitespace when present. Core count, logical
processor count and maximum clock speed are optional positive `Int32` values.
No value is trimmed, truncated or inferred.

The complete collection is validated before one
`IProcessorSnapshotStore.ReplaceAsync` call. A successful empty collection
calls the store with an empty snapshot and clears prior processor state.
Collection, normalization or cancellation failure does not call the store and
preserves the last successful snapshot.

Session ownership, timeout, cancellation, application-owned Türkiye local-time
`CapturedAt`, transaction boundaries and WP-005.3 store behavior are unchanged.
