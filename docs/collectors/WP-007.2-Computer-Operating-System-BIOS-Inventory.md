# WP-007.2 Computer, Operating System and BIOS Inventory

Status: **IMPLEMENTED — INTEGRATION PENDING**

## Contract and ownership

WP-007.2 extends the atomic WP-007 core current-state snapshot with three
single-row modules. Every successful run has exactly one Computer, Operating
System, and BIOS result. Empty, duplicate, malformed, timed-out, or invalid
results prevent all core persistence and preserve the previous current state.

| Module | CIM source | Persisted ownership |
|---|---|---|
| Computer | `Win32_ComputerSystem`, `Win32_ComputerSystemProduct` | name/FQDN/domain, domain role, manufacturer, model, system type, system-product serial, virtualization classification, UUID |
| Operating System | `Win32_OperatingSystem` | caption, version, build, architecture, SKU/edition, product type, installation type, install and boot time, system drive, Windows directory, locale, current time-zone offset |
| BIOS | `Win32_BIOS` | manufacturer, SMBIOS BIOS version, version, release date, serial number, SMBIOS major/minor versions |

Processor counts and total physical memory are not duplicated in Computer.
They remain owned by Processor and physical Memory inventory. Uptime is derived
from `LastBootTime`; it is not persisted.

## Collection and normalization

All commands are read-only `Get-CimInstance` calls with explicit projections
compatible with Windows PowerShell 5.1. Full CIM objects, registry crawling,
operator-provided scripts, credentials, secure-boot keys, and other private
firmware material are excluded.

The three modules use the one Kerberos-only WinRM session already opened for
the target. Strings are trimmed and internal whitespace is collapsed at the
system-module boundary. Missing optional values remain null.

The explicit general placeholder set is:

- `To Be Filled By O.E.M.`
- `Default string`
- `Not Specified`
- `Unknown`

Serial-number normalization additionally treats `System Serial Number` and
`00000000` as unavailable. All-zero and all-FF UUIDs are unavailable; any
other structurally invalid UUID fails validation. Virtual-machine
classification uses a narrow, deterministic manufacturer/model marker list
and remains null when both source values are unavailable.

Target timestamps are parsed through the injected `TimeProvider` and converted
to repository Türkiye-local durable time. Capture time is a separate shared
timestamp produced after all collection has completed.

## Atomic persistence and traceability

Collection and validation finish before `CoreWindowsInventoryStore` begins its
transaction. The store upserts the three singular rows, replaces the existing
core collections, stamps the same `InventoryRunId` on every row, updates the
schedule, and increments `InventoryVersion` in one transaction. A persistence
failure rolls the entire operation back. Repeated successful runs update the
singular rows and do not create duplicates.

Module and transaction events carry target identity and `InventoryRunId`.
Raw CIM output, connection strings, credentials, Kerberos material, tokens,
private keys, and firmware secrets are never logged.

## Schema

Forward migration
`20260728132820_WP0072ComputerOperatingSystemBiosInventory` adds the narrow
Computer and Operating System columns and creates singular
`inventory.WindowsBiosInventory`. Its new-table index is emitted with deferred
dynamic SQL so an idempotent SQL Server batch cannot compile the index before
the table exists. Earlier authoritative migrations are unchanged.

## Integration gate

Repository implementation, deterministic tests, model snapshot generation,
and static idempotent-SQL review do not constitute runtime validation.
Database application, clean Collector installation, real Kerberos/WinRM
collection, repeat-run checks, rollback validation, and event-log inspection
remain exclusively in WP-007.Z.
