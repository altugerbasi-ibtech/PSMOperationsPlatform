# WP-005.7 - Network Adapter and IPv4 Inventory

`NetworkInventoryModule` implements the ADR-006 Network Snapshot boundary. It
uses the successful WinRM session for two allowlisted CIM projections and sends
one fully normalized snapshot to `INetworkSnapshotStore`.

Adapter projection uses `MSFT_NetAdapter`: InterfaceGuid, InterfaceIndex, Name,
InterfaceDescription, PermanentAddress, Speed and
InterfaceOperationalStatus. IPv4 projection uses `MSFT_NetIPAddress` with CIM
filter `AddressFamily = 2` and returns only InterfaceIndex, IPAddress and
PrefixLength. IPv6 is not queried or persisted.

## Identity and correlation

`InterfaceGuid`, canonicalized to GUID `D` format, is Adapter
`StableSourceKey`. Microsoft documents InterfaceGuid as the network interface
GUID and explicitly states InterfaceIndex may change after disable/enable.
InterfaceIndex is therefore used only as a transient join key inside one
collection result.

Adapter disable/enable may change InterfaceIndex without changing identity.
Adapter removal/recreation or driver/provider reconstruction may issue a new
InterfaceGuid; WP-005 then treats it as a new current source identity. MAC
address and friendly name are never used as identity.

Reference: [MSFT_NetAdapter](https://learn.microsoft.com/en-us/windows/win32/fwp/wmi/netadaptercimprov/msft-netadapter).

Every IPv4 result must reference a collected InterfaceIndex. Unknown or
duplicate adapter references fail before persistence. IPv4 identity is
`(AdapterStableSourceKey, canonical address, PrefixLength)`.

## Validation and persistence

- Adapter GUIDs and InterfaceIndex values are unique.
- Required/optional strings and lengths are explicit.
- Speed is non-negative.
- Operational status uses an explicit numeric allowlist.
- Address is canonical IPv4; IPv6 and IPv4-mapped IPv6 fail.
- PrefixLength is `0..32`.
- Duplicate IPv4 identity fails.

Successful empty Network Snapshot clears both tables. Failure, invalid input or
cancellation does not call the store. Persistence deletes IPv4 before Adapter,
inserts Adapter before IPv4 and commits one transaction. Restrictive foreign
keys prevent orphan IPv4 rows.

## Inclusion policy

Collection records observable current state and does not apply operational
usefulness filtering:

- disconnected/down adapters are collected;
- disabled adapters are collected when returned by the source;
- physical and virtual adapters are collected without name, description,
  manufacturer or adapter-type heuristics;
- APIPA `169.254.0.0/16` addresses are collected;
- loopback `127.0.0.0/8` addresses are collected.

Canonical IPv4 and prefix validation still applies. IPv6 and IPv4-mapped IPv6
remain rejected. Active/routable/APIPA/loopback/virtual/disconnected filtering
belongs to later query, analysis, dashboard, DNS discovery or alert layers.
No classification entity, migration or filtering framework is introduced.
