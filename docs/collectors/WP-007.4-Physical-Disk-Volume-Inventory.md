# WP-007.4 — Physical Disk and Volume Inventory

Status: **IMPLEMENTED — INTEGRATION PENDING**

## Architecture Review

The package preserves one shared Kerberos WinRM session, explicit read-only CIM
projections, independent Disk and Volume module contracts, collect-before-
transaction sequencing, and one complete-core transaction. No storage
correlation graph or broad storage DTO was introduced.

## Implementation Review

Physical Disk now uses `Win32_DiskDrive`; Volume uses `Win32_Volume`.
Normalization is ordinal and deterministic. Keys follow the hardware identity
contract. Disk valid-empty and Volume invalid-empty semantics are explicit.
`InventoryModuleContext` has no persistence or credentials, and module results
contain no raw CIM output.

Forward migration `20260728161243_WP0074PhysicalDiskVolumeInventory` renames
the legacy generic keys to `DiskKey` and `VolumeKey` and retains target-scoped
unique indexes. It is repository-only and has not been applied.

## Repository Review

Deterministic unit, component, persistence, model, and idempotent migration SQL
tests cover storage keys, ordering, placeholders, numeric rules, empty
semantics, shared session use, schema consistency, and guards. Runtime
integration remains exclusively in WP-007.Z.
