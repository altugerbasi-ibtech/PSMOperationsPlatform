# WP-007.5 — Network Adapter and IPv4 Inventory

Status: **IMPLEMENTED — INTEGRATION PENDING**

## Architecture Review

Adapter and IPv4 are independent lifecycle modules. Both reuse the one
Kerberos WinRM session, collect before persistence, and contribute to the
complete-core transaction and `InventoryRunId`. Target commands are explicit
read-only CIM projections compatible with Windows PowerShell 5.1.

## Implementation Review

Adapter collection uses `Win32_NetworkAdapter`; IPv4 uses
`Win32_NetworkAdapterConfiguration`. Deterministic identity, ordinal ordering,
placeholder handling, array parsing, canonical IPv4, contiguous subnet masks,
gateways, duplicates, and valid-empty behavior are covered by tests.

Forward migration `20260728175613_WP0075NetworkAdapterIpv4Inventory` renames
the generic keys to `AdapterKey` and `Ipv4Key`, adds selected operational
fields and rowversions, and uses deferred SQL to backfill IPv4 AdapterKey from
the existing same-target relationship before making it non-null. It is not
applied.

## Repository Review

Entity configuration retains the composite
`(NetworkAdapterInventoryId, ManagedServerId)` foreign key, target-scoped
unique keys, ManagedServer-leading run indexes, restrictive delete behavior,
and atomic replacement. No IPv6 or unrelated networking feature was added.
