## Configuration Contract

`SqlTargets` explicitly defines stable name, server, instance, static port,
role, optional version/edition expectation, encryption/trust policy, configured
database list, permission profile, and validation-enabled gate. Validation
rejects duplicate names/endpoints/databases, invalid values, unknown fields,
SQL authentication/secret fields, certificate bypass, and Operations endpoint
misalignment. The sample uses reserved `.invalid` endpoints and synthetic
values; the template remains intentionally unpopulated.

## Query Catalog and Safety

The static query catalog contains bounded read-only metadata queries for core
connection/server facts, supported host platform, documented server settings,
configured databases/files/backups, effective permissions, required metadata
source existence, and availability observations. New query execution rejects
unsafe SQL before command creation. Dynamic SQL is absent.

Operations-database schema and effective runtime permission checks call the
unchanged WP-009.3 and WP-009.4 validators through encrypted Windows-authenticated
`sqlcmd`; their approved logic is not duplicated.
