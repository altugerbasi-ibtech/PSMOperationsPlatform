# WP-005.S2 - Collector Environment Validation Framework

## Outcome

WP-005.S2 adds a versioned, non-interactive PowerShell readiness tool under
`tools/readiness`. It is post-WP-005 validation tooling and does not change
collector runtime behavior.

The only public entry point is `Invoke-CollectorReadiness.ps1`. It supports
explicit `CollectorHost` and `SmokeTest` modes, normalized checks, deterministic
aggregation, JSON/Markdown reports, console summary, and exit codes 0/1/2.

## Security boundary

Checks read local host, files, configuration, service registration, identity,
DNS/TCP, WSMan, and SQL metadata. The tool accepts no credential, password,
`PSCredential`, arbitrary command, or raw connection-string parameter. It does
not remediate, create an output directory, invoke remote commands, mutate SQL,
apply migrations, change services, or change host/target configuration.

Report files in an existing operator-supplied directory are its only intended
write.

## Authoritative repository values

- Target framework: `net10.0`
- Minimum collector OS: documented Windows Server 2022, x64
- Configuration key: `ConnectionStrings:OperationsDatabase`
- Environment prefix: `PSM__`
- Authentication: Windows Integrated
- Transport values: `Auto`, `HttpsOnly`, `HttpOnly`
- Migration: `20260727230000_AddWindowsInventoryCurrentState`
- Inventory schema: eight WP-005 `inventory` tables

## Test strategy

Pester 3.4 is already available in the environment; no package was added.
All external boundaries use injected operation scriptblocks in tests. AST
tests prohibit mutation/remoting commands and SQL mutation statements.

## Live-execution restriction

No real collector host readiness run, target connection, SQL connection, AD
query, or service mutation was performed during implementation. Operators may
run the tool only later under the separate WP-005.S1 controlled gate.
