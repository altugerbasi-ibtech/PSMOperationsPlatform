# WP-007.1A — Approved Inventory Diagnostics Enhancements

## First Approved Work Item

Add durable `InventoryRunId` correlation for one complete core inventory
execution.

WP-007.1 already creates one GUID per execution and includes it in module,
normalization and transaction logs. Persisting that identifier on all eight
core inventory table shapes would widen the WP-007.1 forward migration and
requires an explicit transition rule for pre-existing rows. WP-007.1A shall:

1. associate the same `InventoryRunId` with Computer, Operating System,
   Processor, Memory, Disk, Volume, Network Adapter and IPv4 current-state rows;
2. expose the last successful run identifier on `ManagedServer` if required for
   efficient diagnostics;
3. define the value used for rows predating the migration;
4. add only indexes justified by diagnostic query patterns;
5. verify that failed collection and rolled-back persistence never publish a
   new durable run identifier; and
6. preserve the existing transient structured-log correlation.

## Delivered in WP-007.1

`InventoryVersion` is implemented as a non-negative, monotonically increasing
`bigint` on `ManagedServer`. It increments inside the all-core persistence
transaction only when a successful inventory schedule update is saved.
Collection failures and rolled-back persistence leave the version unchanged.

## Legacy current-state grouping

The WP-007.1A forward migration assigns one generated legacy
`InventoryRunId` per `ManagedServerId` and uses it for all pre-existing core
current-state rows owned by that server. These identifiers group legacy
current state only. They do not reconstruct historical executions, invent
capture timestamps, or claim historical run accuracy.

## Database integration gate

WP-007.1A implementation and deterministic validation may proceed while its
migration remains pending. WP-007 is not complete until an authorized
integration pass reviews all pending migration batch safety, generates a fresh
idempotent script, applies it to a disposable or approved lab database,
validates schema and migration history, builds and locally deploys a fresh
Collector package to PSMLense, validates inventory from PSMLense to myapp01,
and verifies idempotency and rollback semantics.
