# WP-008.4 Architecture Review

Status: **IMPLEMENTED — REVIEW PENDING**

## Boundary

Collector Runtime begins at one committed immutable Execution Plan and ends at
mutable current Execution State plus safe in-process events. Capability,
Decision, and Plan engines are not rerun and plan values are not mutated.
Production automatic activation remains disabled.

## Runtime and handler contracts

The runtime context is immutable and excludes EF, service location,
configuration, credentials, commands, and persistence. Exact ordinal
StrategyCode registration replaces discovery. Descriptors require version 1,
positive PluginVersion, ManagedTargetServer, read-only behavior, and
cancellation. The full plugin model remains WP-008.5 scope.

## Policies, retry, timeout, cancellation

One explicit catalog resolves the existing WP-008.3 timeout, retry,
parallel-group, and throttling references. Runtime owns attempts and retry.
Timeout uses a linked token and remains distinct from external cancellation.
In-process code that ignores cancellation cannot be forcibly terminated; child
process isolation is intentionally absent.

## State, events, metrics, isolation

ExecutionStateSchemaVersion 1 separates Run, Step, and Attempt. RowVersion and
validated transitions protect state. Events follow successful persistence;
state remains authoritative and exactly-once is not claimed. Metrics use
TimeProvider and handler-declared non-negative counts. Step failure is isolated
and independent work continues.

## Persistence and security

The `runtime` schema contains only current Run/Step/Attempt state with explicit
restrictive relationships, unique plan/step/attempt keys, checks, indexes, and
RowVersion. There is no history, event-history, monitoring, target session, or
production collector table. All runtime execution used test fakes only.

Architecture Freeze v1.0 is proposed, not effective, pending WP-008.4 approval.
