# WP-005.2 — Session Ownership and Inventory Orchestration Foundation

## Objective

Refactor WP-004 session ownership so the successful authenticated WinRM
session can be reused by a deterministic empty inventory pipeline. No inventory
collection or persistence is included.

## Repository reconciliation

Opening a session is the existing connectivity probe; the prompt diagram's
“Probe then Session Created” is interpreted as candidate creation followed by
open/probe. In `Auto`, failed HTTPS may create one disposed candidate before a
successful HTTP candidate. “One target session” means one successful retained
session for inventory, consistent with WP-004 and WP-005.1.

WP-005.1 proposed future per-command/total inventory budgets. This sprint's
binding instruction prohibits new timeout behavior, so WP-005.2 preserves only
the existing probe/WSMan timeout and cancellation behavior.

## Delivered scope

- successful session ownership transfer from transport to probe to cycle;
- deterministic disposal of failed candidates and the retained session;
- `IWinRmCommandSession` reusable, serialized invocation and usability boundary;
- `IWindowsInventoryModule` and stable kind order;
- immutable `WindowsInventoryExecutionContext`;
- empty `IWindowsInventoryOrchestrator`;
- duplicate-kind fail-fast validation;
- exception-type failure classification and module isolation;
- cancellation propagation;
- structured events `2350`–`2354`;
- host registration and foundation tests.

## Explicit exclusions

No inventory entity, database/migration change, inventory persistence, concrete
module or concrete inventory command, package, retry or new timeout was added.

## Acceptance evidence

- Empty orchestration completes successfully.
- Reverse registration executes in explicit kind order.
- Every module receives the same target, session, cancellation token,
  `TimeProvider`, logger and correlation ID.
- Non-cancellation failure is safely classified and later modules continue.
- Cancellation stops later modules and propagates.
- Duplicate kinds fail construction.
- Successful target session reaches inventory and disposes once.
- Connectivity persistence rejection skips inventory and still disposes once.
- Failed/timeout/cancelled opens dispose in the transport client.
- Existing WP-004 fallback and connectivity tests remain required.
