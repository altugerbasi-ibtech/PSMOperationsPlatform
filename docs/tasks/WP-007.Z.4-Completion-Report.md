# WP-007.Z.4 Completion Report

## Work Package and Status

WP-007.Z.4 IIS Target Validation is repository-implemented and ready for human
review. Live IIS validation was not executed. This report does not approve the
implementation or authorize Collector execution.

## Architecture and Security Boundary

- Extended the WP-007.Z.3 operational validation framework; no second
  framework or architectural layer was introduced.
- Reused shared configuration loading/validation, result contracts, status
  aggregation, report construction, timing, sanitization, DNS, TCP, exception,
  and output behavior.
- Added only IIS-specific orchestration and checks under
  `tools/validation/iis/`.
- Remote design is explicit Kerberos-only PowerShell remoting with the
  configured WinRM port, `IncludePortInSPN`, and configured TLS policy.
- Windows Collector and SQL Collector identities remain separate.
- No runtime project, behavior, decision, Collector execution, EF model,
  migration, schema, database, IIS configuration, service, process, registry,
  ACL, file, SPN, firewall, binding, pool, site, or application mutation was
  added or executed.

## Changed Files and Framework Reuse

- Extended the existing deployment configuration schema, template, sample,
  validator, documentation, and tests with `IisTargets`.
- Generalized the existing common reporter through backward-compatible report
  title/base-name parameters. WP-007.Z.3 retains its original defaults.
- Added IIS target entry point, checks, mocked tests, operator documentation,
  index entries, and sanitized evidence templates.
- Updated `.gitignore` only to admit WP-007.Z.4 sanitized evidence templates.

## Implemented Checks

1. Connectivity: forward/reverse DNS, WinRM TCP, WSMan, Kerberos session, and
   remote snapshot establishment.
2. Operating system: supported Windows Server, x64, boot/uptime observation,
   pending reboot, domain, time zone, and locale.
3. IIS installation: role, service presence/state, IIS version, and
   `Microsoft.Web.Administration` availability.
4. IIS configuration: sites, applications, virtual directories, bindings,
   host headers, HTTP, and HTTPS with deterministic detailed observations.
5. Application pools: name, runtime, pipeline, identity/gMSA form, state,
   auto-start, and periodic recycling.
6. Worker processes: PID, pool mapping, and state.
7. .NET: Framework and shared-host runtime registry metadata.
8. IIS logging: enabled state, directory accessibility, and free-space facts.
9. Security: Windows, Anonymous, Basic, client-certificate, and pool identity
   observations; enabled Basic Authentication warns.
10. Filesystem: IIS/application/log paths, existence, readability, and free
    space without write probes or invented capacity thresholds.
11. SQL endpoint: DNS/TCP-only reachability with no database connection.
12. Collector compatibility: deterministic mandatory-check aggregation and
    constituent check IDs; never starts the Collector.

## Configuration Contract

`IisTargets` is a required non-empty array in the existing shared deployment
configuration. Names are syntax-validated, compared case-insensitively, and
duplicates are rejected. A command-line `ComputerName` must select exactly one
configured target; omission selects all targets in deterministic order.
Kerberos-only and port-qualified-SPN values are now required by cross-field
validation. No credential, endpoint-specific authentication setting, or new
configuration format was introduced.
