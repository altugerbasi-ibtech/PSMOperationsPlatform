# WP-005.S1 - Controlled Lab Smoke Test

## Status

Phase A preparation is complete. Phase B has not been authorized or executed.
WP-005 remains completed and architecture-review passed. This package is a
post-implementation, non-production validation gate.

## Objective

Validate the existing read-only chain:

```text
eligible target -> WinRM HTTPS-first policy -> reusable session
-> seven ordered modules -> normalization/validation
-> current-state persistence -> read-only SQL verification
```

No product feature, migration execution, target configuration change, or
production deployment is included.

## Repository decisions

- ADR-006 owns current state by logical snapshot.
- Adapter and IPv4 form one atomic, IPv4-only Network Snapshot.
- `CapturedAt` is application-owned Türkiye local time.
- Failed/cancelled modules preserve their previous successful snapshot.
- Successful modules may commit independently; all inventory is not one
  cross-module transaction.
- `WindowsCollectorCycle` owns and disposes the successful command session.
- `Auto` falls back from HTTPS to HTTP only for TLS failure, connection
  refused, timeout, WinRM unavailable, or protocol failure.
- There is no one-shot mode. Phase B uses the existing service/polling
  lifecycle; no utility is added.

## Execution gate

Phase B requires a recorded collector host, lab target FQDN and non-production
confirmation, target transport policy/ports, dedicated test SQL database, test
Windows identity, migration status, network readiness, no-remote-mutation
confirmation, and explicit execution approval. Any ambiguity stops execution.
Migration and database cleanup each require separate explicit approval.

## Safety

Stop on suspected production scope, identity/connection ambiguity, schema or
migration mismatch, unexpected mutation, partial snapshot, orphan IPv4, target
isolation failure, security-boundary violation, or session leak evidence.
Preserve evidence and propose a corrective Work Package if source changes are
needed.
