# WP-007.1 Release SQL Package

## Purpose

WP-007.1 converts the existing ordered EF Core migrations into one
deterministic, idempotent, DBA-owned SQL release package. It does not connect to
SQL Server and does not change application startup or runtime permissions.

## Generate

From a clean repository revision:

```powershell
.\scripts\release\Build-PSMOperationsSqlPackage.ps1 `
  -Version 1.0.0-rc1
```

Output is written to `Release\Database`:

```text
PSMOperations-v1.0.0-rc1.sql
PSMOperations-v1.0.0-rc1.sql.sha256
PSMOperations-v1.0.0-rc1.manifest.json
```

The builder performs Release restore/build, rejects pending EF model changes,
and runs:

```text
dotnet ef migrations script --idempotent
```

It fails if source state is dirty, a required command fails, the migration
expectation is invalid, SQL is missing/empty, or checksum generation fails.

## Determinism

SQL is normalized to UTF-8 without BOM, CRLF, and one terminal newline. The
manifest has stable ordered fields and no timestamp, user, machine, local path,
server, database, credential, or secret. It records the source commit, exact
migration set, latest migration, filenames, and SHA256.

## CI Artifact

The `release-sql-package` workflow runs on Windows for version tags and manual
dispatch. It publishes only the SQL, checksum, and manifest under artifact name
`PSMOperations-Database-v{Version}`.

## DBA Boundary

Automatic migrations are prohibited. Application startup must never call
`Database.Migrate()` or `EnsureCreated()`. A DBA must review backups,
compatibility, permissions, transaction behavior, deployment sequencing,
rollback, and the target environment before executing the SQL.

Real SQL execution, validation, upgrade rehearsal, and production certification
remain exclusively WP-007.Z.
