# WP-009.1 Release SQL Package

## Purpose

WP-009.1 generates a deterministic, idempotent, DBA-owned SQL Server release
package from the repository's existing EF Core migrations. It never connects
to SQL Server and changes no runtime or production code.

## Generate

Run from a clean committed repository revision:

```powershell
.\scripts\release\Build-PSMOperationsSqlPackage.ps1 -Version 1.0.0
```

The release entry point used by CI is:

```powershell
.\scripts\release\Publish-PSMOperationsSqlPackage.ps1 -Version 1.0.0
```

Both write these files to `Release\Database`:

```text
PSMOperations-v1.0.0.sql
Manifest.json
Checksums.sha256
```

## Build Gates

The builder restores and builds the solution, executes
`dotnet ef migrations has-pending-model-changes`, and generates SQL with:

```text
dotnet ef migrations script --idempotent
```

Packaging fails when source state is dirty, source metadata cannot be
resolved, restore/build fails, pending model changes exist, migration
generation fails, SQL is missing or empty, or integrity metadata is invalid.

## Artifact Contract

SQL is UTF-8 without BOM with CRLF and one terminal newline.
`Manifest.json` contains:

- `ProductVersion`
- `BuildDate`
- `GitCommit`
- `SQLScriptName`
- `SHA256`

`BuildDate` is the source commit timestamp normalized to UTC, making it stable
for a given Git commit. `SHA256` identifies the SQL bytes.
`Checksums.sha256` covers the SQL and manifest payload files in fixed order.
The checksum catalog does not hash itself.

## CI Publication

`.github/workflows/release-sql-package.yml` runs for version tags or an
explicit manual version. It publishes the three files as
`PSMOperations-Database-v{Version}` and fails when any file is absent.

## Security and Deployment Boundary

Automatic EF Core migrations are prohibited. The application must never call
`Database.Migrate()`. Package generation performs no database update,
`sqlcmd`, SQL connection, permission change, or infrastructure operation.

An authorized DBA must review and execute the SQL under separately approved
change control. Database deployment, schema validation, permission validation,
rollback execution, and production certification are outside WP-009.1.
