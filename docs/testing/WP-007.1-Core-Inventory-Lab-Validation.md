# WP-007.1 Core Inventory Lab Validation

This procedure is prepared for the approved path
`PSMLense.ae.local -> myapp01.ae.local`. It must not be executed without the
separate operational, database and service-control approvals.

## Entry gates

Record the package hash, source revision, service executable and gMSA, target
FQDN and `ManagedServer.Id`, HTTP port 5985, migration
`20260728093000_WP0071CoreInventoryReliability`, database identity, Türkiye
timezone evidence and the approved evidence directory. Exactly one Collector
instance may be active.

Seed one enabled target. Set `NextInventoryAttemptAt` to `NULL` and preserve
the pre-run connectivity, scheduling and all eight inventory-table projections.
Do not infer the target ID from its FQDN.

## First run

Start the existing service only under the approved service-control step.
Verify the current-cycle WinRM session succeeds with Kerberos and the persisted
connectivity state becomes `Reachable`. Correlate one inventory run ID.

Expected current state:

- Computer: exactly one row.
- Operating System: exactly one row.
- Physical Memory, Processor, Disk, Volume, Adapter and IPv4: exactly the
  validated counts returned by the equivalent allowlisted CIM projections.
- Processor and Volume must be non-empty.
- Memory, Disk, Adapter and IPv4 may be empty.
- Every core row has the same Türkiye-local `CapturedAt`.
- `LastInventoryAttemptAt` and `LastInventorySuccessAt` equal the successful
  capture time, failure count is zero, failure category is null, and
  `NextInventoryAttemptAt` is six hours later.

Verify no duplicate `(ManagedServerId, ModuleKey)` or
`(ManagedServerId, StableSourceKey)` values. Left join IPv4 to Adapter on both
adapter ID and ManagedServer ID and require zero unmatched rows.

## Repeat and failure

Make inventory due again through the separately approved seed operation and
run a second unchanged cycle. Counts and logical keys must remain identical,
singular counts remain one, collection rows do not grow, and the common capture
time advances.

Use an approved non-destructive collection-failure simulation. Confirm no core
table changes, connectivity remains independently successful, the inventory
failure category and backoff are persisted, and events identify target, FQDN,
run, failed module, safe category and retry time. Scan logs for connection
strings, credentials, tickets and raw CIM output.

## SQL verification

Use Integrated Authentication and a known target ID. Query scheduling columns
from `configuration.ManagedServer`; query every core table by
`ManagedServerId`; group child keys with `HAVING COUNT_BIG(*) > 1`; compare
`MIN(CapturedAt)` with `MAX(CapturedAt)` across the union of all core tables;
and validate the composite Adapter/IPv4 join.

## Cleanup

Restore the original seed and logging level, remove only approved test
conditions, preserve evidence, then perform one approved recovery rerun.
Never delete adapter rows before IPv4 dependents and never apply a migration
from the Collector runtime.
